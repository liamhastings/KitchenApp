# 2026-07-26

Full UI redesign plus four features. Restock now has a food catalog, price
estimates, a real kitchen inventory, and recipe suggestions.

---

## Setup for collaborators (Expo Go)

If you are **not** building with Xcode, you need two commands and nothing else.
No Xcode, no CocoaPods, no `pod install`.

```bash
npm install
npx expo start --go
```

Then scan the QR code with Expo Go on your phone.

### The one gotcha

**`npx expo start` on its own will not work for you.** Because `ios/` is checked
into this repo, the Expo CLI defaults to targeting a native development build —
which you don't have and can't produce without Xcode. You'll get a QR code that
does nothing useful. The `--go` flag is what forces Expo Go.

### Why this is safe

Verified today against the SDK 57 docs and by bundling in Go mode
(1094 modules, zero resolve errors):

- `expo-sqlite` — *"Included in Expo Go"*. The one exception is SQLCipher, which
  Expo Go doesn't support; we use plain `openDatabaseSync` with no encryption,
  so it doesn't apply.
- `expo-font` — *"Included in Expo Go"*.
- `@expo-google-fonts/*` are pure JS plus `.ttf` assets — no native code.
- The `patches/expo-modules-jsi` workaround only matters when compiling
  natively. Irrelevant in Expo Go.

### `npm install` is not optional

Today added `@expo-google-fonts/inter` and `@expo-google-fonts/instrument-serif`
as new dependencies, imported directly in `App.tsx`. With a stale
`node_modules`, Metro fails to resolve them and you get a bundle error
immediately — on any platform. That's a lockfile change, not an Xcode thing.

### If you *are* building natively (iOS simulator or device)

```bash
npm install
cd ios && LANG=en_US.UTF-8 pod install
npm run ios      # full rebuild — a Metro reload is not enough
```

`expo-font` is a new native module, so `ios/Podfile.lock` changed. See the
README's "Known environment issues" for the Xcode 26.0.1, `LANG`, and Node
version caveats on this machine.

## What was configured today

### Scandinavian redesign

`src/ui/theme.ts` is now the whole design system — palette, spacing, radii, font
tokens, and a `type` scale that every screen reads from.

- Warm unbleached paper instead of grey, hairline rules instead of shadows,
  three muted pigments carrying all meaning: spruce (full / primary), ochre
  (some), clay (none / need / destructive).
- **Instrument Serif** for anything that names a thing — screen titles, recipe
  and item names, tallies. **Inter** 400/500/600 for everything else. Loaded at
  runtime via `useFonts` and gated on before the first frame.
- Custom fonts on iOS ignore `fontWeight`, so weight has to come from the family
  name. Centralising every text style in `type` is what stops a stray
  `fontWeight: '700'` from silently doing nothing.
- Tab bar emoji replaced with letterspaced uppercase labels and a small active
  dot. `StatusPill` became a tinted wash with a dot; `HaveNeedToggle` became one
  segmented control instead of two competing buttons.

### Food catalog

`src/data/catalog.ts` — 180 groceries, each with a section, a typical purchase
unit, and a Canadian price.

- **Autocomplete** on the grocery *and* kitchen add fields via the shared
  `ui/components/FoodSuggestions`. Typing "chicken" offers breast, thighs,
  drumsticks, wings, ground, broth. Picking one borrows its aisle so the item
  groups correctly. Free text is never rejected — the list always ends with an
  `Add "…"` row. Grocery shows price and unit; the kitchen doesn't.
- **Price estimate** on the grocery list, per row and as a footer total.

Two limits are deliberate and stated in the UI rather than hidden:

1. It prices **one unit of each item**. Parsing `"2 cups; 1 tbsp"` into a
   multiplier would be the same guess the app already refuses to make.
2. Unpriced items are **reported, not zeroed** — "N not priced". Silently
   counting them as $0 would understate the total.

Prices are estimates baked into the file — typical Canadian shelf prices before
tax, not live or regional data.

### Your Kitchen (was Inventory)

- Renamed in the UI only. `inventory` is still the term in the schema, types and
  repos, and the tab route is still named `Inventory`.
- **Starts empty.** The store now reads `listInventory()` (tracked-only) instead
  of listing every ingredient the seeded recipes mention.
- **Long-press an item's name to remove it.** This *untracks* — it deletes the
  user's statement and returns the item to never-said. Not the same as `none`,
  and the item plus every recipe using it are left untouched (verified: 3 recipe
  links survived).

### Putting shopping away

Ticking a grocery item is reversible, so it deliberately does **not** write
inventory — un-ticking would have to un-write it, and there's no honest answer
to what it reverts to. Instead a **"Put N in your kitchen"** button appears once
something is ticked. One-way, explicit.

It writes `full`, and this is deliberately *not* the `statusAfterHave` rule:
confirming "have it" on a recipe must not inflate a `some`, because you're
affirming a belief you already held, but buying genuinely adds stock. Both rules
live in `logic/matching.ts` and the check suite asserts they stay different.

### What can I make?

Your Kitchen leads with recipes derived from what's on hand (`splitCookable`):

- **You can make** — every ingredient is `full` or `some`.
- **Almost there** — within a few of ready, closest first.

An untracked ingredient is never counted as on hand, so the app never promises a
meal it can't back up. But untracked doesn't disqualify a recipe either — it
holds it in "almost there", where the note reads "N still unconfirmed" rather
than implying you're missing them.

### Housekeeping

- `normalizeName` moved to `logic/normalize.ts` so `logic/` stays free of SQLite
  imports and still runs under plain Node. `itemRepo` re-exports it.
- Deleted dead code: `Card`, `SectionHeader`, `listAllItemsWithStatus`.
- Closed a coverage gap: 5 of 42 seeded ingredients weren't in the catalog, so
  checkouts produced unpriced rows. Now 42/42 with no normalized-name
  collisions.
- `check:logic` gained assertions for catalog search, the free-text fallback,
  name-collision safety, unpriced-not-zeroed, the put-away rule, and
  `splitCookable`'s treatment of untracked ingredients.

Dependencies added: `expo-font`, `@expo-google-fonts/inter`,
`@expo-google-fonts/instrument-serif`. `app.json` gained the `expo-font` plugin;
`ios/Podfile.lock` regenerated.

## Future work

### Worth doing next

- **Catalog autocomplete on the AddRecipe ingredient fields.** Grocery and Your
  Kitchen both have it; the recipe form is the odd one out, and it matters most
  there. Ingredient names are the join key between recipes and the kitchen — type
  "chicken thigh" in one place and "Chicken thighs" in another and you silently
  get two items, which directly degrades "what can I make". Would reuse
  `FoodSuggestions`, roughly 20 lines. It would also let the tap-to-cycle section
  picker go away for catalog items.
- **An `npm run go` script** (`expo start --go`) plus a README section for Expo
  Go collaborators, so nobody has to rediscover the `--go` flag.

### Known gaps

- **No tests below `logic/`.** The repos and the store have zero coverage —
  `check:logic` only exercises pure functions. Biggest structural gap; needs a
  real test runner.
- **`getAllRecipeItemIds()` runs a synchronous SQLite query inside render** on
  both RecipesScreen and InventoryScreen. Free at 8 recipes, not free forever.
- **No way to edit a recipe** — only create and delete.
- **Nothing flags that you already own an item** when you add it to the grocery
  list.

### Before anyone builds to a real device

- **Bundle ID is `com.liamhastings.restock`.** Anyone building to hardware needs
  to change it and set their own signing team.
- **`git config user.name` is `sosa`** on this machine, so commits won't
  obviously read as Kailen in the log. The email is the right GitHub-linked one,
  so attribution still works.
